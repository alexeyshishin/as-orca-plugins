# Git Gutter

Цветная полоса слева от номера строки в [Orca](https://github.com/stablyai/orca): показывает, какие строки файла изменились относительно `git HEAD`. Зелёный — строка добавлена, жёлтый — строка изменена, красный маркер — рядом удалённые строки.

## Статус

Этап 2 плана. Полоса и диф работают для `.js`, `.mjs`, `.ts`, `.json`; в каталог (`orca-catalog.json`) плагин пока не добавлен, установить его так нельзя — только через `orca plugin dev load`.

## Как включить

Git Gutter — отдельный режим редактора (CodeMirror 6), не замена встроенного редактора по умолчанию: Orca открывает `.js`/`.mjs`/`.ts`/`.json` во встроенном Monaco-редакторе, а Git Gutter выбирается вручную иконкой в переключателе вида (`priority: "option"`), как Live Markdown для `.md`. Открыть файл во встроенном редакторе и в Git Gutter одновременно в двух вкладках можно, они не конфликтуют.

**Честно о текущем виде**: редактор Git Gutter заменяет для файла встроенный Monaco-редактор и пока не имеет подсветки синтаксиса и автодополнения — только моноширинный текст, курсор, выделение, подсветка активной строки и полоса изменений. Это сознательный разрыв с Monaco на этом этапе; при работе с большими файлами или когда нужна подсветка, используйте обычный редактор и переключайтесь в Git Gutter только чтобы увидеть полосу.

## Значение полосы

- **Зелёная** — строка добавлена (её не было в `HEAD` или в файле, который Git Gutter сопоставил как базу).
- **Жёлтая** — строка изменена.
- **Красная** — маркер после удалённого блока строк (удаление в начале файла помечает первую строку, в конце — последнюю).
- **Заштрихованная серая** — Git Gutter не знает, менялся ли файл: наведите курсор на полосу, всплывающая подсказка (`title`) называет причину (черновик не сохранён, конфликт слияния, бинарный файл, файл или diff больше лимита, несколько файлов с одинаковым содержимым, репозиторий слишком большой, и т. п.). Заштрихованная полоса — это честное «не знаю», а не «не менялось»: пустая обычная полоса возможна только когда Git Gutter явно сопоставил файл с `HEAD` (без изменений) или нашёл однозначную базу (изменён).

## Принятые ограничения (из плана)

- **L1. Черновик.** Несохранённый черновик не даёт меток: заштрихованная полоса, пока файл не сохранён и окно не получило фокус.
- **L2. Только локальные воркспейсы.** WSL и SSH пока не поддерживаются.
- **L3. Фильтры git.** При `autocrlf` и `.gitattributes` чистые файлы иногда не совпадают с blob из `HEAD` по сырому содержимому; второй вариант id (с LF, без BOM) снижает долю таких случаев, но не снимает их полностью.
- **L4. Одинаковое содержимое.** Если открытый текст совпадает с несколькими файлами разной судьбы (один не менялся, другой изменён; или два изменённых файла с разной базой), Git Gutter не угадывает — показывает заштрихованную полосу с причиной «несколько файлов с одинаковым содержимым».
- **L5. Размеры.** База больше 512 КиБ, файл-кандидат больше 1 МиБ, бинарный файл, список файлов репозитория (`ls-tree`) больше 32 МиБ, больше 2000 кандидатов на изменение — заштрихованная полоса.
- **L6. Устаревание.** После `git commit`, `reset`, `checkout` в другом окне или терминале база обновится при следующем фокусе окна, не мгновенно.
- **L7. Запуск `git`.** Выполняется в репозитории воркспейса с его настройками; `core.fsmonitor` отключён флагом на каждый вызов, внешние diff-драйверы и `textconv` не используются.
- **L8. Переименование без `git add`.** Видно как удаление старого пути и untracked новый файл: новый файл показывается целиком зелёным, а не диф против старого содержимого.
- **L9. Большие диффы.** При превышении лимита построчного сравнения (LCS) диф упрощается до крупных блоков; перемещённый блок текста показывается как удаление плюс добавление, а не как перемещение.

## Что делает воркер и зачем нужен `trusted-worker`

Манифест объявляет профиль `execution: "trusted-worker"` — воркер исполняется в отдельном процессе Node.js на машине пользователя с его правами, потому что это единственный способ дать плагину доступ к `git`: сам фрейм редактора (CodeMirror в `editor/index.html`) работает без сети и без файловой системы. Что именно запускает воркер — только на чтение, никогда на запись в `.git`:

- `git rev-parse HEAD` — текущий `HEAD` воркспейса;
- `git ls-tree -r -z HEAD` — список blob-ов, закэширован по паре «воркспейс + HEAD»;
- `git status --porcelain=v1 -z --untracked-files=all` — какие файлы изменены, добавлены, переименованы, не слиты;
- `git hash-object --no-filters --stdin-paths` — хэши содержимого файлов-кандидатов, чтобы сопоставить их с текстом, который прислал фрейм;
- `git show HEAD:<путь>` — содержимое базовой версии изменённого файла.

Воркеру передаются только 40-символьные hex git-blob-id, посчитанные фреймом по тексту документа, и id воркспейса из актуального списка Orca — ни путь файла, ни его содержимое фрейм воркеру не передаёт и не может передать. `git diff`, `--textconv` и `--ext-diff` не используются никогда; каждый вызов `git` — через `execFile` с массивом аргументов (без текстовой командной строки), с `--no-optional-locks`, `-c core.fsmonitor=false`, таймаутом и лимитом вывода.
